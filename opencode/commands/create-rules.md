# /create-rules — AGENTS.md generator

> ⚠️ **NEW PROJECTS ONLY.** This command generates a fresh `AGENTS.md` from codebase patterns.
> It will **refuse to run** if `AGENTS.md` already exists in the project root — use it on
> greenfield repos or repos that have never had an `AGENTS.md`.
>
> If you want to update an existing `AGENTS.md`, edit it directly.

## Usage

```
/create-rules
```

Run from the project root.

## Preflight (mandatory — abort if guard triggers)

```bash
# Refuse to overwrite an existing AGENTS.md
if test -f AGENTS.md; then
  echo "AGENTS.md already exists. Refusing to overwrite."
  echo "Edit AGENTS.md directly, or delete it first if you want a clean regeneration."
  exit 1
fi
```

**If AGENTS.md exists → stop here. Do not proceed.**

## Survey phase

Read the codebase to extract patterns:

1. **Language and toolchain** — detect from `Cargo.toml`, `package.json`, `pyproject.toml`, `go.mod`, `Makefile`, etc.
2. **Directory structure** — `ls` top-level dirs; infer module / package layout.
3. **Existing conventions** — scan for `.editorconfig`, `rustfmt.toml`, `.eslintrc*`, `pyproject.toml [tool.ruff]`, etc.
4. **Test patterns** — locate test directories / files; identify test runner.
5. **CI / build** — check `.github/workflows/`, `Makefile`, `justfile`, `scripts/`.
6. **Existing docs** — read `README.md` if present for stated conventions.
7. **Recent git log** — `git log --oneline -10` to see commit-message style.

## Output

Write to: `AGENTS.md` in the current directory (project root).

## AGENTS.md template

```markdown

> Generated by `/create-rules` on <date>. Edit to keep current.

## Repo layout

<Summarise discovered directory structure and what each top-level dir contains.>

## Language & toolchain

<Language(s), package manager, build tool, test runner.>

## Build & test

```sh
# Build
<detected build command>

# Test
<detected test command>

# Lint
<detected lint command, or "none detected">
```

## Conventions

<Naming, formatting, error-handling patterns extracted from existing code.>

## Commit message style

<Pattern inferred from git log. If no pattern found, default to conventional commits.>

## Agent behaviour notes

<Any project-specific rules for agents operating in this repo:
- Which directories are safe to edit vs. read-only.
- Sensitive paths to avoid.
- Any non-standard tool or workflow.>

## Open questions

- [ ] <anything that couldn't be determined from static analysis>
```

## Discipline

- Do not fabricate rules. If a pattern can't be observed, leave the section as a `<placeholder>` or ask.
- Do not reference external services, CI systems, or tools not present in the repo.
- After writing, report: `AGENTS.md written at <path>` (one line).
